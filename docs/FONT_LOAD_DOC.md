# 《Crisis Beat》（PS1 日版）字库装载链路技术文档

> 依据 SLPS_014.exe 逆向、ePSXe 存档 RAM 分析、v8/v13/v15/v17 多版本实测确认。
> 配套代码：`codecs.py`、`engine417.py`~`engine449.py`（装载器/坐标/槽位/差异验证）。

## 一、结论速览

1. **字库有压缩**：字库数据（字形/几何）以压缩流形式内嵌在光盘数据区 14 处窗口中，装载器按定长窗读取后解压。
2. **装载链路**：光盘 DATA.0 → 数据区 14 处内嵌流（F2 窗 + FB 窗）→ 装载器解压（F2_VA/FB_VA 覆盖区）→ RAM 容器 → VRAM（TSB 页 + 槽位）。
3. **F2 窗 = 2072B，FB 窗 = 7264B**；解压后得到 8192B（F2' TIM2'）与 24576B（FB' bankB 等）等字形/几何数据。
4. **日文码表**：文本编码为 1B 码（0x01-0xEF）+ 2B 扩展码（`FF xx`/`FE xx`），映射到 VRAM 的 TSB 页 + 字形地址。

## 二、装载器整体流程

### 2.1 内存中的固定窗口

```
F2_VA  = 0x800A9D3C   # F2' 流起点（覆盖区）
FB_VA  = 0x800AA560   # FB' 流起点
FB_END = 0x800AC1C0   # FB' 结束

sp2 = FB_VA - F2_VA        # 2084
sp3 = FB_END - FB_VA       # 7264
```

- 装载器按 2072B 定长窗读取（F2WIN=2072），FB 窗紧随其后（FBWIN=7264）。
- 覆盖区映射：`u_ov(va) = 0x250000 + (va - 0x7F8D12A8)`（逻辑地址坐标系）。
- 装载器实际从**数据区 14 处内嵌流**装载 F2'/FB'（坐标列表见 2.3）。

### 2.2 槽位与 VRAM

- 字形槽位：slot73 = TIM1 bankA 行0-11（码 0x01-0xBF 渲染）；slot74 = TIMC TSB31 9行（码 0x200-0x28F 新字）。
- 槽 73/74 每个场景包加载 10 处（entry1/3/5/7/9/11/12/13/14/15）。
- VRAM 页映射：<0x100 → TSB5；<0x200 → TSB29；>=0x200 → TSB31。
- 字形地址：`U=(码&0xF)<<4, V=码&0xF0`。

### 2.3 14 处数据区窗口坐标（逻辑）

```
[ 0] @112D2C80   [ 1] @113F8010   [ 2] @11478D30   [ 3] @1150AF90
[ 4] @115A1480   [ 5] @115DC070   [ 6] @1161D910   [ 7] @1163ED00
[ 8] @116774D0   [ 9] @118676C0   [10] @11A53390   [11] @11A67CE0
[12] @11B05710   [13] @11B19490
```

每处 = F2 窗 2072B + FB 窗 7264B（FB 窗紧跟 F2 窗，间距 0x818=2072）。

### 2.4 窗口与解压

- `codecs.unpack_stream`（0x8001E0F0 路径）对 F2 窗/FB 窗解压：
  - F2 窗解出 8192B（TIM2' 字形/几何），FB 窗解出 24576B（bankB 等）。
- 14 处 FB' 流均一致（engine447 验证 14 处 F2 窗 == v8、FB 窗 == v13）。

## 三、字库是否压缩？—— 是

- 字库数据以压缩流存放：F2 窗内是块流（tag 如 0x73），FB 窗内是块流（0x73）。
- `engine434` 解析 v8.FB' 流块结构：块0 tag=73 消耗2661 输出8192；块1 tag=73 消耗2735 输出8192；块2 tag=73 消耗1868 输出6208。v13.FB' 结构：块0 消耗2552 输出8192；块1 消耗2629 输出8192；块2 消耗1829 输出8192。
- 字库数据**压缩格式与文本所在场景包相同的 pak 块流**（tag 0x73/0x74/0x72 等）。

## 四、日文文本码表

### 4.1 码表结构（见 `codetable_master.json`）

- 0x00-0x7F：假名/符号（kana_00_7F），含 々/ー/…/数字/片假名/汉字 悪安。
- 0x80-0xEF：汉字（kanjiA_80_EF）。
- `FF xx` 双字节汉字：
  - xx >= 0x80：VRAM code = xx（直接映射）
  - xx < 0x80：VRAM code = xx + 0x3A（偏移映射）
- 0xF0-0x1AF 用 `FF xx`（xx = 码 - 0xF0），0x1E0-0x2DF 用 `FE xx`（xx = 码 - 0x1E0）。
- 控制字节：F0=转义、F1=换行、F2/F3=块标记、F4/F5=清屏/滚屏、F6=块尾。

### 4.2 汉化码表（codetable_v3.json）

- 当前汉化新码表 `codetable_v3.json`：538 个码位（汉字 + 假名 + 符号 + 拉丁字母），映射到 VRAM 槽位。
- 注意：**v3 是汉化版新码表**（把日文假名码位置换为新字形码），不是日文原表；日文原表见 `codetable_master.json` 的 kana_00_7F / kanjiA_80_EF / bankB_FF10_BF。

### 4.3 VRAM 字形映射（FF 索引 → VRAM code）

- FF idx >= 0x80 → 直接映射（如 FF 0x83→0x83=明）。
- FF idx < 0x80 → 偏移映射（如 FF 0x58→0x92=日）。
- 10 个测试点全部验证通过（见 `progress_0904.md`）。

## 五、汉化补丁的装载相关改动（v8/v15/v17）

- 覆盖区 `0xA28A80` 是 v8 时代注入的 MIPS 代码（原版此处全零）。
- 槽 73/74 在 entry1/3/5/7/9/11/12/13/14/15 各加载 10 处。
- v17 布局：原版基底 + v15 布局（覆盖区 F2'/FB'、槽 73/74×10、两处 HUD 文本、14 处数据区 F2=v8 满窗 2072B + FB=v13 FB' 流 7264B）+ 60 文本小簇（9760B）。
- 10×15011B 大簇、14×5727B 恢复簇、MIPS 代码区保持原版（防死机关键）。

## 六、验证与自检

1. 用 `codecs.py` 对 F2 窗解压 → 应得 8192B（含 TIM 头 `10 00 00 00 08 00 00 00`）。
2. 对 FB 窗解压 → 应得 bank'/几何数据。
3. 检查 14 处 FB' 窗与覆盖区 FB' 流一致（engine447 PASS）。
4. 文本码表用 `engine137` 解码 → 与译文一致；VRAM 渲染用 `codetable_v3` 公式 `U=(码&0xF)<<4 V=码&0xF0` 验证字形位置。
