   - 结尾孤立单字（血/君/苦/遇）为被截断残句；「，」为引擎悬空标点；均为文本流原始状态，翻译时原样保留。

   - 覆盖全部 243 框，按场景命名 30 个 ENTRY（序章/劫船/逃亡/反派/求救/组队/炸弹/BOSS/双结局/分头行动等）。

## 二、字库与编码体系结论（沿用此前已确认结果，汇总备查）

### 字库存储与显示
- **光盘上的字库是压缩存储的**（LZ 压缩流；以 32 字节未压缩字形全盘探针扫描，0 命中）。想修改字库（如替换为中文字形），必须先破解并解压其光盘资源打包/压缩格式。
- **VRAM 中为 4bpp**：x640-768 / y0-320 区域，每字 8 字节宽 × 16px 高；VRAM 布局为 512 行 × 2048 字节（Layout A）。
- 双字库叠加：nibble 0 / nibble 1 两套字库写入同一 VRAM 区域，靠 CLUT 切换显示；**游戏对话实际使用 nibble 1 层**。

### 文本编码（最终完整规则）
| 码点 | 含义 |
|---|---|
| 0x00-0x7F | BankA 假名/符号区（单字节） |
| 0x80-0xEF | BankA 汉字区（单字节） |
| 0xF1 | 句中停顿（解码为 ∥） |
| 0xF3 | 说话人标记结束符；结构 = [ID字节]F3，出现在 F6 换行后的行首 |
| 0xF6 | 换行 |
| 0x03 | ・（03 03 03 = ・・・） |
| FF xx | 双字节。xx=00-0F → BankA 0xF0-0xFF 行末 16 字；xx=10-BF → BankB 连续 176 格 |

- BankB 坐标：bx1664 + col×8，y256 + row×16；低 nibble 在左像素。
- 全盘文本解码**零未知码**。
- **说话人 ID→角色名映射未破解**（约 132 种 ID，最常见 0x3C/0x50），需逆向引擎文本绘制调用才能确定；翻译数据中按原样保留 ID 的解码假名（ま/ざ/イ/だ…）。

### 数据组织
- 条目表位于 LBA 1184，0x1FD4 字节 = 2037 个 u32 LE 偏移；条目表完全单调递增。
- 读取方式：`file_off = lba*2352 + 24`，每扇区取 2048 字节。
- ENTRY 160-222（第一份）与 ENTRY 358-422（第二份）为**同一剧本的两份完全相同拷贝**（ENTRY 间隔恰为 198），实际唯一对话约 30 个 ENTRY / 243 框。
